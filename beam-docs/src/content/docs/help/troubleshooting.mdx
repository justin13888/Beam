Organised by what you see. If you have a specific HTTP status instead, go to

## The server will not start

<Steps>
1. Read the container logs — Beam refuses to start on invalid configuration and says which
   variable is at fault.
2. Check PostgreSQL is up and `BEAM_DATABASE_URL` points at it.
3. Run `./verify-config.sh`.
4. If it starts and then exits, suspect a failed migration. Check the logs for migration errors.
</Steps>

## Sign-in bounces back and I am still signed out

Almost always the session cookie not surviving the round trip.

<Steps>
1. Check `BEAM_SERVER_URL` and `BEAM_WEB_URL` are the URLs your **browser** actually uses — not
   `localhost` when you are connecting from another machine.
2. Check `BEAM_COOKIE_SECURE` matches your scheme. `true` over plain HTTP means the browser
   discards the cookie and nothing visible explains it.
3. Try without third-party cookie blocking, or in a normal (non-private) window.
4. Start from the app rather than reloading the callback URL — it is single-use, and reloading it
   fails by design.
</Steps>

## "OIDC login unavailable"

Beam cannot start a sign-in flow.

<Steps>
1. `BEAM_OIDC_ISSUER`, `BEAM_OIDC_CLIENT_ID` and `BEAM_OIDC_CLIENT_SECRET` must **all three** be
   set. Any missing one means OIDC counts as unconfigured.
2. Check none of them is set to an empty string — comment them out instead.
3. From the server, confirm the issuer's `.well-known/openid-configuration` is reachable.
4. Check the redirect URI registered with your provider is exactly
   `<BEAM_SERVER_URL>/v1/auth/callback`.
</Steps>

## I am not an admin

<Steps>
1. `BEAM_OIDC_ADMIN_CLAIM` must be set. With no claim configured, **nobody** is an admin.
2. Confirm your provider actually asserts that claim, with the value in `BEAM_OIDC_ADMIN_VALUE`,
   in the **ID token** — not just in a userinfo response.
3. **Sign out and back in.** Admin is recomputed only at sign-in; nothing changes in a live
   session.
</Steps>

## The scan finds nothing

<Steps>
1. The library path is the path **inside the container**. If you mounted `/srv/media` at
   `/videos`, use `/videos/...`.
2. Check your files use an indexed extension — see
   [Managing libraries](/operate/libraries/#which-files-get-indexed). `.iso` and `.vob` are not
   indexed.
3. Check the server can read the directory.
4. Look at the admin Logs tab for per-file failures.
</Steps>

## Scan refused: library root is empty

The rescan failed with "Library root contains no video files but video files are indexed". Beam
found the library's directory but no video files Beam can index anywhere beneath it — no file with
one of the [indexed extensions](/operate/libraries/#which-files-get-indexed) — while the catalogue
still lists video files for that library. That is almost always a volume that is not mounted: an
unmounted bind mount, dropped NFS or SMB share, or disk that failed to attach leaves its mount point
behind empty, or holding only files such as `.not_mounted`, `.DS_Store` or `Thumbs.db`. Beam refuses
to reconcile rather than mark the library's whole catalogue missing. Nothing was changed.

<Steps>
1. Check the admin Logs tab. The error entry names the library and how many video files are
   indexed; expand its **Details** for the root path (`path`), the library id and the count
   (`indexed_video_files`). The admin notification also names the root.
2. From inside the container, confirm the path shows your media. If it does not, fix the mount (see
   [Your media directory](/install/#your-media-directory)) and restart the container if needed.
3. Rescan once the files are visible.
4. If you removed every video from the library deliberately, delete the library rather than
   rescanning it.
</Steps>

## My TV show is called "Season 01"

Expected, and the most common layout mistake. A show's name comes from the episode file's
immediate parent directory, so `Show Name/Season 01/episode.mkv` produces a show called
"Season 01".

Put episodes directly under a folder named after the show, then rescan. See
[the layout guidance](/operate/libraries/#directory-layout-for-tv).

## My episodes are showing up as movies

Beam recognises exactly one episode pattern: `SxxEyy`. Names using `1x02`, `Episode 2` or plain
sequential numbering classify as movies. Rename to include an `SxxEyy` marker and rescan.

## Two different films merged into one entry

Movies are grouped by their cleaned title **and year**, so two films with the same name stay apart
as long as each filename carries its year — `Dune.1984.mkv` and `Dune.2021.mkv`. Add the year to
any filename that lacks one and rescan.

Films a Beam version before this grouping merged stay merged: the upgrade cannot tell which file
belongs to which film, so it leaves the entry as it is and names it in an admin-log warning
("could not be keyed"). To split it, move or rename the files so each carries its year — a new
path is indexed afresh under the right title, and the old entry is removed once its files are.
The same warning names duplicate entries an older version created when enrichment renamed a title;
those resolve the same way.

## A title has no poster

<Steps>
1. Wait. Enrichment runs after the scan, in batches.
2. Without `BEAM_TMDB_API_TOKEN`, non-anime titles are never enriched. This is silent by design.
3. Check the parsed title in the UI. If it looks wrong, the filename is why — fix it, rescan, and
   re-enrich.
4. Check the admin Status tab to tell "not tried yet" from "tried and found nothing".
</Steps>

## A file will not play

Start with [When a file won't play](/using/playback-compatibility/) — Beam never transcodes, so
this is usually your browser lacking a codec rather than a fault. Try another browser first.

## Playback stops partway through

<Steps>
1. If it stops at the same point every time, the file is likely truncated or corrupt. Confirm it
   plays elsewhere.
2. If the point varies, suspect the network or disk throughput. Beam streams the original file, so
   a high-bitrate remux needs real bandwidth — there is no automatic quality drop.
3. Offer a smaller version of the movie so viewers can choose one — see
   [Managing libraries](/operate/libraries/#multiple-versions).
</Steps>

## "Source video file not found"

The catalogue has the file but the path does not exist. A bind mount is missing, the library
moved, or the file was deleted outside Beam. Fix the mount, then rescan.

## Titles or episodes have nothing to play after a disk went offline

The titles are still listed, but their versions on that disk are gone from the source list, can't
be streamed, and have left continue-watching and history. Beam hid the files it could no longer
find rather than deleting them — see
[When files go missing](/operate/libraries/#when-files-go-missing). Nothing, including anyone's
resume point, is lost yet. (A title whose only file is missing stays listed with nothing to play;
hiding it is tracked in [#183](https://github.com/justin13888/beam/issues/183).)

<Steps>
1. Bring the disk or share back, then rescan (or just wait: the watcher and the periodic rescan
   restore files as they reappear at the same path).
2. Do it within the grace period — 30 days unless `BEAM_MISSING_FILE_GRACE_DAYS` is set. A scan
   after that removes the files, and everyone's progress on them, for good.
3. If a scan reported that it **could not read** part of the library, the admin Logs tab has a
   warning listing the folders or files (`failed_paths` in its **Details**). Files at or beneath
   them were left alone; fix the permissions or the share and rescan.
</Steps>

## Everything returns 429

Rate limiting, which applies to sign-in and search only.

<Aside type="tip">
Behind a reverse proxy, every user can share one bucket because they all appear to come from the
proxy's IP. Set `BEAM_RATE_LIMIT_TRUST_FORWARDED_FOR=true` — but only if your proxy **overwrites**
`X-Forwarded-For`. If it appends, clients can forge the header and bypass the limit.
</Aside>

## Health says "degraded"

Read the `checks` object in the `/v1/health` response — in practice this is the database being
unreachable or refusing connections. See [Monitoring and logs](/operate/monitoring/).

## Still stuck

[Getting help](/help/support/) lists what to include so the report can be acted on.
