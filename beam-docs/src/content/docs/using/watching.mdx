Press play and Beam begins sending the file's bytes. Your browser does the decoding. Nothing is
converted along the way, which is why playback starts quickly and why it depends entirely on what
your browser can handle — see [When a file won't play](/using/playback-compatibility/).

## The player

The player offers the usual controls — seeking, volume, fullscreen and keyboard shortcuts.
Seeking anywhere in a title works immediately, including into parts that have not been buffered:
Beam serves any byte range of the file on request rather than streaming it strictly start to
finish.

## Choosing a source

A **movie** or a **TV episode** can have more than one file indexed against it — say a
high-bitrate rip and a smaller re-encode. When it does, the player offers a picker, and each option
is labelled with its actual resolution and codec, read from the file itself:

```
1080p · h264
720p · h264
```

A file whose video stream Beam could not probe is listed as **Original**.

Beam lists them best first and marks that one the **primary**: the default edition before a
named one such as a *Director's Cut*, then the tallest picture, the higher bit rate and the larger
file. The web player starts with the primary; the Android and Apple apps start with the best source
your device can actually play.

Switch to a smaller one when your connection cannot keep up: this is how Beam handles constrained
bandwidth. It has no adaptive streaming and will never switch for you, because there is no
transcoder generating alternatives on the fly. Every option in that list is a file that already
exists on the server.

If a movie or episode shows no picker, only one file is indexed for it. Adding another version is
something an administrator does — see [Managing libraries](/operate/libraries/#multiple-versions).

## Subtitles

Beam now knows every subtitle track of a title: the ones inside the video file, with their real
format, language and flags (forced, SDH), and the subtitle files sitting next to it — `.srt`,
`.vtt`, `.ass` and `.ssa`. The subtitle files are served to players as they are, and SubRip and
WebVTT files also as WebVTT, the one format a browser can show.

**The players do not show subtitles yet.** There is no track selector in the web player or the
apps so far; that is player work still to come. Until then, download the file and play it in a
desktop player, which picks up the subtitle files beside it if you download those too.

Some subtitles will stay out of a browser's reach even then: a track inside the video file is never
extracted from it, and ASS, SSA and image subtitles (a Blu-ray's PGS, a DVD's VobSub) are never
converted. A browser can only show a subtitle track that exists as a `.srt` or `.vtt` file beside
the video.

## Your position is saved

Beam records where you stopped as you watch, so you can close the tab and come back — on any
version of the title. Watching to the end marks it watched. See
[Resume and history](/using/continue-watching/).
