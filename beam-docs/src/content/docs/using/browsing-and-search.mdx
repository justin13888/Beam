---
title: Browsing and searching
description: Find titles by browsing your libraries or with search, filters and sorting.
---

There are two ways to reach a title: browse a library, or search.

## Browsing

Each library the administrator has added appears as its own collection of titles. Opening one
lists everything indexed in it.

## Explore

The Explore view searches and filters across everything you can see. Filters available:

| Filter | Values |
|---|---|
| Type | Movie or show |
| Genre | Any genre present in your library |
| Year | A range, from and to |
| Minimum rating | 6, 7, 8 or 9 out of 10 — movies and shows alike; an unrated title is left out |
| Sort by | Title, year or rating |
| Order | Ascending or descending |

A title with no value for the sort — no year, no rating yet — goes **last** in either order, rather
than first when you sort ascending.

Filters are reflected in the URL, so a filtered view is a link you can bookmark or share with
another user of the same server.

## Search

Search runs on the server and matches on **title similarity**, so a near-miss or a small typo
still finds the right thing. Results update as you type, with a short pause so that a fast typist
does not fire a query per keystroke. Matches are listed in the sort you chose — by title unless
you picked another — not ranked by how closely they match.

Two things it does not do:

- It does **not** search inside descriptions, cast lists or subtitles — titles only.
- It only finds titles that have been **indexed** and have a file on disk right now. A title whose
  files have all gone missing — an unplugged drive, a deleted folder — is left out of browsing and
  search until a file comes back, though a link to its page still works. If something is missing,
  the library may need a scan; ask an administrator, or see
  [Managing libraries](/operate/libraries/#when-files-go-missing) if that is you.

## What search does not cover

Search matches the **title** Beam shows — the one derived when it indexed the file, or the
provider's once metadata enrichment has run — not the filename or the folder it sits in. If a title looks wrong, that is the derived title rather than a search problem — see
[Managing libraries](/operate/libraries/#how-beam-decides-what-a-file-is).
