---
title: Keycloak
description: Register Beam as a Keycloak client and grant admin through a group.
---

import { Aside, Steps } from "@astrojs/starlight/components";

This assumes Keycloak is already running and reachable from both your browser and the Beam
server, and that you have a realm your users sign in to.

<Steps>

1. **Create a group for Beam admins** in your realm — for example `beam-admin` — and add the users
   who should administer Beam.

2. **Create a client for Beam.** Use the OpenID Connect protocol, turn **client authentication**
   on (Beam is a confidential client), and enable the standard authorization-code flow. Set the
   valid redirect URI to exactly:

   ```
   <BEAM_SERVER_URL>/v1/auth/callback
   ```

   Keycloak generates a client secret for a client with authentication enabled; copy it. Beam
   always sends a PKCE `S256` challenge, so you may require PKCE on the client if you like.

3. **Put the group in the ID token.** Keycloak does not include group membership in tokens by
   default. Add a protocol mapper of type **Group Membership** to the client, with:

   - token claim name `groups`;
   - adding to the **ID token** enabled — Beam reads the ID token only, not userinfo or the access
     token;
   - **full group path** off, so the value is `beam-admin` rather than `/beam-admin`.

   Attach the mapper to the client itself, or to a client scope assigned to it as a *default*
   scope, so it applies without Beam having to request an extra scope.

4. **Configure Beam:**

   ```sh
   BEAM_OIDC_ISSUER=https://<keycloak-host>/realms/<realm>
   BEAM_OIDC_CLIENT_ID=<client id>
   BEAM_OIDC_CLIENT_SECRET=<client secret>
   BEAM_OIDC_ADMIN_CLAIM=groups
   BEAM_OIDC_ADMIN_VALUE=beam-admin
   ```

   The default `BEAM_OIDC_SCOPES` (`openid profile email`) is enough. If you left full group path
   on, set `BEAM_OIDC_ADMIN_VALUE=/beam-admin` instead — the match is exact and case-sensitive.
   Leave `BEAM_OIDC_CLIENT_AUTH_METHOD` unset: Keycloak's **Client Id and Secret** authenticator
   accepts the secret by HTTP Basic, Beam's default, as well as in the form.

5. **Check it.** Restart Beam, sign in as a member of `beam-admin`, then open
   `<BEAM_SERVER_URL>/v1/me` in the same browser. It should show `"is_admin": true`.

</Steps>

<Aside>
The issuer must match the `issuer` in
`https://<keycloak-host>/realms/<realm>/.well-known/openid-configuration` exactly. If Keycloak
sits behind a reverse proxy, make sure it is configured with its public hostname, or the issuer it
advertises will not be the one Beam was given.
</Aside>

**Signing in on a TV.** Turn on **OAuth 2.0 Device Authorization Grant** in the Beam client's
capability configuration, then restart Beam. See
[Sign-in on a TV](/operate/identity-and-access/#sign-in-on-a-tv-or-another-device-without-a-browser).

See [Identity and admin access](/operate/identity-and-access/) for how admin is recalculated and
revoked, and [troubleshooting](/help/troubleshooting/#i-am-not-an-admin) if `is_admin` stays
`false`.
