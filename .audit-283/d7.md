## Outcome

Enrichment picks the same match, and sweeps the same rows, whatever the input order and whichever store backs it:
- A full tie between providers goes to the earlier provider, as the code's own docs say.
- A `NaN` popularity cannot panic the ranking.
- `fetch_due` selects the same batch in Postgres and in the in-memory double, and the shared contract pins it.
- A negative or non-finite duration tag is rejected at probe time.

## Findings

- **index-IMPL-001 / index-TEST-001** `beam-index/src/services/enrichment/matcher.rs:131-181` (show variant `:184-229`). The doc says ties break by "provider list order (earlier providers…)", and so do `composite.rs:5-7, 25-26`. `Iterator::max_by` returns the *last* of equal maxima, so a later provider wins a full tie. No test builds one.
- **index-TEST-041 / index-IMPL-017** `matcher.rs:177-178, 225-226`. `partial_cmp(..).unwrap()` on provider-supplied popularity panics on `NaN`. `EnrichmentControl::candidates` (`control.rs:405-426`) already uses `total_cmp`, so the copies disagree.
- **index-TEST-002 / DOMAIN-TEST-002** `beam-index/src/repositories/enrichment.rs:189-215` against `beam-domain/src/repositories/enrichment.rs:198-213`. SQL uses `ORDER BY next_attempt_at ASC`, where Postgres puts NULLs last. The in-memory double sorts `Option`, where `None` comes first. With a `limit` below the due count they enrich different titles. The contract (`beam-domain/src/repositories/contract.rs`) has no `fetch_due` case; only a SQL-shape check exists (`sql_shape_tests.rs:784-801`).
- **index-TEST-033** `beam-index/src/probe/metadata.rs:33-46, 180-186`. `parse_duration_string` accepts `-1`, `NaN` and `inf` through `f64::parse`, so a `-01:00:00` tag becomes a -3600s duration.

## Decisions taken

These are the run's decisions under the autonomy contract. Nobody has reviewed them.

1. Tie-break: doc or code.
   Taken: the doc. The earlier provider in priority order wins a full tie (`.rev()` before `max_by`, or an explicit index tie-break). Three doc comments record that intent, and the composite orders providers deliberately.
   Rejected: rewriting the docs to "last wins", which nothing motivates.
   Reverses: drop the tie-break and reword the three docs.
2. `fetch_due` order.
   Taken: never-attempted rows first, then the earliest `next_attempt_at` (`NULLS FIRST` in SQL). That matches the double, and a newly indexed title is enriched promptly.
   Rejected: NULLs last, which can starve new titles behind a long retry queue.
   Reverses: switch both stores to NULLs last and update the contract case.
3. Non-finite or negative durations.
   Taken: treat them as absent (`None`), as other unparseable tags are.
   Reverses: accept them again.
