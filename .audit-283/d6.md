## Outcome

A shipped deployment's logs carry the four event classes NFR-403 requires: scan lifecycle, enrichment lifecycle, authentication outcomes, and admin-mutating actions. Each is a structured event. The default filters, in the binary, `compose.beam.yaml` and the Helm chart, include the Beam crates that emit them.

## Findings

- **GAP-001 (NFR-403, FR-604)** `docs/requirements/non-functional.md:164-166`.
  - (a) The built-in default filter is `beam_server=debug,kynos=debug` (`beam-server/src/logging.rs:33-35`). Compose sets `RUST_LOG=beam_server=info,tower_http=debug,axum=debug` (`compose.beam.yaml:26`), and the chart sets `logLevel: "beam_server=info,tower_http=info"` (`charts/beam/values.yaml:49`). None of them enables `beam_index`, where scan and enrichment events are emitted (`beam-index/src/runtime.rs:179-443`, `beam-index/src/services/index.rs`). `tower_http` and `axum` are not dependencies any more.
  - (b) No login, logout, device-login or session event is logged at `info` or above in `beam-server/src/routes/auth.rs` or `beam-auth/src/utils/login.rs`. `session_store.rs:237,284,295` logs at `debug` under `beam_auth`, which is filtered out.
  - (c) No admin mutation (library create/delete, user disable, access change, fix-match, field locks, re-enrich) emits a log event or an `admin_logs` row. `AdminLogCategory::Auth` (`beam-entity/src/admin_log.rs:23`) is written only in a test (`beam-index/src/services/admin_log.rs:200`).

## Decisions taken

These are the run's decisions under the autonomy contract. Nobody has reviewed them.

1. The default filter.
   Taken: `beam_server=info,beam_index=info,beam_auth=info,beam_domain=info,kynos=info` everywhere. One constant in `logging.rs` is mirrored by the compose and chart defaults, and `check:compose-invariants` / `check:chart-invariants` assert the agreement if that is cheap.
   Rejected: leaving per-deployment strings that disagree, which is how they drifted.
   Reverses: restore the three strings.
2. Which events also go to the `admin_logs` table that the admin viewer reads.
   Taken: admin mutations (category `System`) and sign-in failures and successes (category `Auth`), with no secrets, tokens or IP beyond what `sessions` already stores.
   Rejected: process logs only, which leaves the admin viewer blind to who changed what.
   Reverses: drop the `admin_logs` writes and keep the tracing events.

## Surface

- **Configuration default:** the default log filter.
- **Admin log contents:** new rows of existing categories.
- No wire shape changes.

## Constraints

- No gate is weakened.
- Logged fields never include a session token, cookie, IdP token or device code.
