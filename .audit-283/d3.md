## Outcome

On Android, media bytes, downloads and images carry the Beam session only to the server's own origin. A trusted-on-first-use certificate pin is honoured only for the host it was pinned for, and only within the certificate's validity window. That is the rule the core already enforces, and Android now decides it by calling the core instead of keeping a second copy. URLs the server returns resolve only on its own origin.

## Findings

- **android-TEST-004** `beam-android/core/media/src/main/kotlin/dev/beam/android/core/media/http/BeamDataSources.kt:80-89`. `OkHttpDataSource.Factory(...).setDefaultRequestProperties(headers)` attaches the session cookie header to every request, including requests to another host and after a redirect. `BeamHttpClientFactory.trusting(fingerprints)` (`:36-45`) takes no host. Image fetches are scoped and tested (`ServerCallFactory.kt:51/89`, `BeamImageLoaderTest.kt:134-175`); media fetches have neither.
- **android-IMPL-001** `beam-android/core/media/.../http/TofuTrustManager.kt:36-61, 107-112`. Kotlin re-implements the core's pin predicate and has diverged from it. The core requires a pinned fingerprint, a certificate covering the host, and the validity window (`beam-client-core/src/tls.rs:162-176`). Android checks only the fingerprint, so Media3, Coil and downloads accept an expired pinned certificate that the core rejects. `normalizeFingerprint` duplicates `tls.rs:114-120`. Android never reads `PlaybackHttpConfig.pinned_host` / `ServerHttpConfig.host`, while Apple does (`AVPlayerEngine.swift:79`).
- **core-TEST-015** `beam-client-core/src/servers.rs:127`. `absolute_url` uses `base.join(..)`, which returns another host for an absolute `https://other/x`. Stream, part, sidecar and artwork URLs from the server can therefore leave its origin, and no test says whether they may.

## Decisions taken

These are the run's decisions under the autonomy contract. Nobody has reviewed them.

1. Where the pin predicate lives.
   Taken: export one core function (e.g. `pinned_certificate_accepted(der, host, fingerprints, now_unix) -> bool`, built from `tls::describe`, `covers_host` and the window check) and call it from `TofuTrustManager.checkServerTrusted`. ADR-0012 puts shared client logic in the core.
   Rejected: patching the Kotlin copy. That keeps two predicates that have already drifted once.
   Reverses: inline the checks in Kotlin and drop the export.
2. Off-origin URLs from the server.
   Taken: `absolute_url` refuses (or reports) a URL whose origin differs from the server's, and the session never attaches off-origin.
   Rejected: following any absolute URL. A hostile or misconfigured server could then send the viewer's cookie to a third party.
   Reverses: restore `base.join` behaviour.

## Surface

- A UniFFI API addition (the predicate export).
- TLS trust behaviour: an expired or wrong-host pinned certificate is now refused on Android, as it already is in the core.
- Callers are in this repository: Android, and Apple for `absolute_url`.

## Constraints

- No gate is weakened.
