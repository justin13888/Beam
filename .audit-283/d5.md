## Outcome

A `5xx` problem document on any client-facing route carries a fixed, generic `detail`. The cause goes to a structured `tracing` event, never to the wire (NFR-108). `POST /v1/logout` reports a session-store failure instead of answering `204` while the session stays valid on the server (FR-109). Tests pin both.

## Findings

- **GAP-002 (NFR-108)** `docs/requirements/non-functional.md:46-50`. Any signed-in viewer who hits a 500 gets raw internal error text, such as a database driver message, in the problem `detail`. Kynos takes `detail` from `Display` (kynos-macros-0.4.0 `src/lib.rs:522`). `MetadataError::InternalError` displays as `"Internal metadata service error: {0}"` (`beam-server/src/services/metadata.rs:982-983`) and reaches the wire as `MediaBrowseError::Internal(err.to_string())` (`beam-server/src/routes/media.rs:161-165`). 71 sites in `beam-server/src/routes/*.rs` build `Internal(e.to_string())` / `Internal(err.to_string())` (`grep -c`). The database-failure tests check status and problem type only, never `detail` (`beam-server/src/routes/media_tests.rs:821-860`).
- **GAP-003 (FR-109)** `beam-server/src/routes/auth.rs:1087-1089`: `let _ = session_store.delete(&token).await;`. A store failure is discarded, the cookie is cleared, and `204` is returned, so the session stays valid server-side while the client believes it signed out. `logout-all` does propagate its error (`auth.rs:1102-1110`). Nothing tests a store failure on logout.
- **server-IMPL-026** `beam-server/src/routes/admin.rs:642,681,733,769,843` (plus `trickplay.rs:90`, `auth.rs:906`, `stream.rs:168`). `let internal = |e: sea_orm::DbErr| X::Internal(e.to_string())` is repeated per handler. This is the mechanism by which the cause reaches `detail`.

## Decisions taken

These are the run's decisions under the autonomy contract. Nobody has reviewed them.

1. Where the cause goes.
   Taken: `Internal` variants keep the cause for logging (a `tracing::error!` with the error as a field at the mapping site, or a `#[source]`). They render one fixed detail, e.g. "An internal error occurred."
   Rejected: keeping the text on the wire. NFR-108 forbids exposing implementation details, and the server faces the public internet.
   Reverses: restore `Display`-derived detail.
2. Logout under a store failure.
   Taken: answer `500 #internal` and leave the cookie in place, so the client can retry.
   Rejected: silently answering `204`. The client would believe a revocation that never happened.
   Reverses: restore `let _ =`.

## Surface

- **Error contract:** the `detail` text of `5xx` problems changes. Types and statuses do not.
- **Logout:** a store failure is now `500` instead of `204`.
- **Clients:** in-repo clients match on problem `type` and never on `detail` (`beam-client-core/src/transport.rs` problem parsing), so nothing in the repository breaks.

## Constraints

- No gate is weakened.
- No other surface changes.

- `an_internal_failure_never_echoes_its_cause`: a table over every route module whose store can fail, asserting the fixed detail.
- `a_session_store_failure_on_logout_is_500_and_keeps_the_cookie`.
