# Component: `beam-web`

Status: describes the target module layout. Where current code differs, that is called out
explicitly as "today." See [docs/architecture/overview.md](../architecture/overview.md) and
[ADR-0003](../architecture/decisions/ADR-0003-oidc-bff-auth.md) for the auth model this client
implements.

## Role

`beam-web` is the reference (and, for this push, only) client: a Vite + React 19 + TanStack Router
single-page app styled with Tailwind and shadcn/ui, talking to `beam-server`'s REST API.

## Data layer: REST only, GraphQL removed

Today, `beam-web` runs two parallel data layers: a generated `openapi-fetch` REST client
(`src/api.gen.ts`, `src/lib/apiClient.ts`) used only by the auth routes (`login.tsx`, `register.tsx`)
and the video player (`media.$id.tsx`), and an Apollo/GraphQL client (`@apollo/client`,
`src/gql.ts` generated by `@graphql-codegen/*`) used by everything else that talks to the catalog —
`routes/explore.tsx`, `routes/libraries.tsx`, `routes/libraries.$id.tsx`, and `routes/admin.tsx` all
import `gql`/`useQuery`/`useMutation` from `@apollo/client`.

This push removes GraphQL entirely, matching the server-side removal described in
[server.md](server.md): `@apollo/client`, `graphql`, `@graphql-codegen/cli`,
`@graphql-codegen/typescript`, `@graphql-codegen/typescript-operations` are dropped from
`package.json`; `src/gql.ts` and its `codegen.ts` config are deleted; the `export-schema`/`codegen`/
`codegen:full` package.json scripts (which shelled out to `cargo run --bin export_schema` in
`beam-stream`) are deleted, since that binary no longer exists. Every route that used Apollo is
rewritten against the single generated REST client (`src/api.gen.ts`, regenerated via
`openapi-typescript` from `beam-server`'s OpenAPI spec, wrapped by `openapi-fetch` in
`src/lib/apiClient.ts`) and TanStack Query (`@tanstack/react-query`) for caching/loading state. The
`export-openapi`/`codegen:openapi`/`codegen:openapi:full` scripts already present in `package.json`
become the only codegen path.

## Routing (target)

File-based routes under `src/routes/`, using TanStack Router's `createFileRoute`. Target set,
building on today's files:

- `index.tsx` — home / continue-watching (continue-watching is new: backed by the `playback_progress`
  table via a new `GET /v1/playback/continue-watching`-shaped endpoint on `beam-server`).
- `libraries.tsx` / `libraries.$id.tsx` — library browse and library detail, rewritten off REST +
  TanStack Query in place of today's Apollo usage.
- `media.$id.tsx` — media detail with the player (see below); rewritten off REST.
- `explore.tsx` — becomes the search route (or is renamed to `search.tsx` for clarity); rewritten off
  REST.
- `admin.tsx` — admin area (library CRUD, logs, enrichment/scan progress); rewritten off REST, and
  gains an SSE subscription to `beam-server`'s admin progress endpoint (see [server.md](server.md))
  in place of any GraphQL subscription usage.
- `profile.tsx` — retained, adjusted for the OIDC session model (see below).
- `login.tsx` — collapses to a minimal "sign in" button that redirects to `beam-server`'s OIDC
  start endpoint. Today's `login.tsx` is a username/password form posting to
  `POST /v1/auth/login`; that entire form and its `login.test.tsx` are replaced.
- `register.tsx` — **deleted entirely.** There is no self-service registration under OIDC; identity
  is provisioned JIT from the IdP on first login (see
  [ADR-0003](../architecture/decisions/ADR-0003-oidc-bff-auth.md)).

`__root.tsx` retains its `Header`/`RouteError`/router-context shape, but its `MyRouterContext` drops
`apolloClient` once Apollo is removed.

### Scaffold cleanup

`src/routes/demo/` (`form.address.tsx`, `form.simple.tsx`, `tanstack-query.tsx`), `src/components/
demo.FormComponents.tsx`, and `src/hooks/demo.form-context.ts`/`demo.form.ts` are leftover scaffolding
from the `create-tsrouter-app` project generator and are removed as part of this cleanup — they are
not part of any real route.

## Auth session handling

Today, `hooks/auth.tsx`'s `AuthProvider` stores a JWT `token` and `user` object in `localStorage`,
populated from the `AuthResponse` body returned by `POST /v1/auth/login`/`register`, and sends that
token nowhere except as a `session_id` cookie set by the server (`login`/`logout` still round-trip
through `credentials: "include"`, but the client separately keeps its own copy of the token/user in
`localStorage`, which is redundant with the cookie and is a vestige of the pre-OIDC JWT design).

Target: `AuthProvider` becomes a thin context that calls `GET /v1/auth/me` on mount to discover the
current session (relying entirely on the httpOnly session cookie — no token of any kind is read,
stored, or sent by client-side JS). `login` becomes "navigate the browser to `beam-server`'s OIDC
start endpoint" (a redirect, not an API call returning credentials). `logout` becomes `POST
/v1/auth/logout` followed by clearing local React state — there is nothing in `localStorage` to
remove because nothing is ever written there.

## Player

Today, `media.$id.tsx` renders a bare HTML5 `<video>` element, fetching a short-lived stream token
via REST and pointing `<video src>` at `beam-server`'s byte-range endpoint (`<video src>` can't set
custom headers, hence the token-in-URL pattern already used today).

Target: the player is rebuilt on **Vidstack**, adding: a source-quality picker when a title has
multiple `files` rows (see [data-model.md](../architecture/data-model.md)'s `files.quality` column
and multi-version delivery scenario), resume-from-position support (reading/writing
`playback_progress`), and periodic progress-reporting beacons back to `beam-server` during playback.
The underlying transport is unchanged: direct HTTP Range requests against `beam-server`'s streaming
route — no HLS manifests, since the server never transcodes (see
[ADR-0004](../architecture/decisions/ADR-0004-never-transcode.md)).

## Tooling

- **Biome** (`biome.json` at the repo root) is the sole lint/format tool for `beam-web` — `bun run
  check`/`lint`/`format` (and their `:fix` variants) all shell out to `biome`. There is no separate
  ESLint/Prettier configuration.
- **Test stack**: `vitest` (runner), `msw` (network mocking — see `src/test/handlers.ts`,
  `src/test/server.ts`), `@testing-library/react`/`dom`/`user-event` (component testing), `jsdom`
  (DOM environment). `src/test/setup.ts` wires MSW's server into the vitest lifecycle. This pattern —
  mock the REST boundary with MSW rather than hitting a real `beam-server` — is what makes
  `bun run check`/`vitest run` runnable with zero backend infrastructure, mirroring the Rust side's
  zero-infrastructure testing rule in CLAUDE.md.
