# Architecture Decision Records

This directory records significant, settled architectural decisions for Beam, in
context/decision/consequences format. Each ADR is numbered permanently at creation time. **ADR
numbers never change or get reused**, even when a later decision supersedes an earlier one — a
superseding decision is recorded as a new ADR that references and supersedes the old one, which stays
in place (marked superseded) for historical record rather than being renumbered or deleted.

| ADR | Status | Decision |
|---|---|---|
| [ADR-0001](ADR-0001-modular-monolith.md) | Accepted | A single `beam-server` binary absorbs `beam-index` and `beam-auth` in-process (the gRPC/tonic indexer process was deleted); internal crate modularity is preserved, not abandoned. |
| [ADR-0002](ADR-0002-rest-only-api.md) | Superseded by ADR-0010 | One REST, OpenAPI-first API versioned `/v1`, with progress delivered over SSE; the GraphQL stack was deleted entirely. |
| [ADR-0003](ADR-0003-oidc-bff-auth.md) | Accepted | OIDC Authorization Code + PKCE via the backend-for-frontend pattern replaced username/password auth; the browser holds only a session cookie, never IdP tokens. |
| [ADR-0004](ADR-0004-never-transcode.md) | Accepted | Never transcode or remux media server-side; deliver via full download, direct-play, or selection among pre-existing indexed file versions. |
| [ADR-0005](ADR-0005-sessions-in-postgres.md) | Accepted | Sessions live in a Postgres `sessions` table behind a `SessionStore` trait; Redis/Valkey was dropped from the stack entirely. |
| [ADR-0006](ADR-0006-cameo-enrichment.md) | Accepted | Indexed titles are enriched via the `cameo` crate (TMDB + AniList) behind a provider-agnostic `EnrichmentProvider` trait, run as an async post-scan worker. |
| [ADR-0007](ADR-0007-vendored-ffmpeg-local-dev.md) | Accepted | A `vendored-ffmpeg` Cargo feature (LGPL-only, static) makes `cargo test --workspace` hermetic locally; CI and container images keep dynamically linking system FFmpeg. |
| [ADR-0008](ADR-0008-image-cdn-direct.md) | Superseded by ADR-0015 | Poster/backdrop images are served as direct TMDB/AniList CDN links; no server-side image proxy or cache. |
| [ADR-0009](ADR-0009-release-engineering.md) | Accepted | `mise.toml` is the single source of truth for tools and commands, invoked by both CI and the `hk` git hooks; Conventional Commits drive one product version, and release-please cuts `chore: release` pull requests that publish multi-arch GHCR images. |
| [ADR-0010](ADR-0010-openapi-3-2-kynos.md) | Accepted, implemented | Retain REST, adopt OpenAPI 3.2 and typed SSE, and replace Salvo with Kynos so routing and the description derive from one declaration. Shipped on Kynos 0.1.0; the browser toolchain cannot read 3.2 yet, so `beam-web` is stood down rather than forked. |
| [ADR-0011](ADR-0011-mutation-testing.md) | Accepted | Mutation testing (`cargo-mutants`) runs as an advisory loop, never a merge gate, with surviving mutants resolved by hardening the code before adding a test; repository behaviour is covered by one contract test bound to the fake, to `sea_orm::MockDatabase`, and to an opt-in `pg-integration` Postgres tier that leaves NFR-201 unconditional. |
| [ADR-0012](ADR-0012-native-client-rust-core.md) | Accepted | Native clients share one Rust core (`beam-client-core`) whose REST client is generated by spargen and exposed over UniFFI; codec capability matching, trust-on-first-use, and the progress queue live there once. WebView auth is an interim with a native-mint seam; Android CI is JVM-only. |
| [ADR-0013](ADR-0013-apple-client-two-engines.md) | Accepted | The Apple client owns its player shell and swaps two engines underneath: `AVPlayer` wherever AVFoundation can open the container, and a sample-buffer engine over a Matroska demuxer in `beam-client-core` where it cannot. Liquid Glass on an iOS 26 / macOS 26 floor; the Xcode project is generated. tvOS is blocked on a Tier 3 Rust target and on having no web view to lift a cookie from. |
| [ADR-0014](ADR-0014-adaptive-streaming-rejected.md) | Accepted | Adaptive streaming is rejected outright rather than deferred: packaging-only HLS/DASH is remuxing under another name, and ABR across independently indexed encodes cannot switch seamlessly. Playback capability belongs to the client — capability matching, client-side demux, and a client-driven downgrade to a smaller indexed source. |
| [ADR-0015](ADR-0015-artwork-served-by-beam.md) | Accepted | Beam serves all poster, backdrop and thumbnail art itself from `/v1/artwork`, cached on disk and keyed by the provider URL, so no viewer's client contacts a provider CDN. Supersedes ADR-0008 and settles the revisit condition it left open in #70. |
| [ADR-0016](ADR-0016-bring-your-own-idp.md) | Accepted | Beam is bring-your-own-IdP permanently: no bundled identity provider is shipped or supported for deployment, and the bundled Dex stays a dev fixture. The setup bar is lowered with provider quickstarts instead. Extends ADR-0003 and settles #149. |
| [ADR-0017](ADR-0017-device-authorization-grant.md) | Accepted | Clients with no browser sign in by the OAuth 2.0 device authorization grant, run server-side against the IdP: the client polls with an opaque handle and receives the ordinary `beam_session` value, never an IdP token. Cookie-only until kynos can declare any-of security; Android phones keep the WebView and add "Sign in with a code"; device sign-in is the default only without a usable browser. Settles #151. |
| [ADR-0018](ADR-0018-kubernetes-helm-chart.md) | Accepted | Kubernetes is supported through `charts/beam`: exactly one server replica with the Recreate strategy (the indexer is not leader-elected), migrations serialised on a Postgres advisory lock, external Postgres, libraries mounted read-only by construction, and a liveness probe that ignores the database. Rendered-output invariants gate it in `mise run ci`. Settles #76. |
| [ADR-0019](ADR-0019-telemetry-posture.md) | Accepted | Telemetry is opt-in with no default collector: `BEAM_TELEMETRY_URL` names an operator-chosen OTLP endpoint, and a weekly report carries aggregate library counts only, each as a coarse range -- no title, path or identifier -- whose exact bytes an admin can preview before opting in. Playback data never leaves the server; opt-in playback telemetry (#143) keeps only operator-local daily counts of failures, rebuffers and source switches. |
